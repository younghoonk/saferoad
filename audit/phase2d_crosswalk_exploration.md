## 2. 신구대조표 형태 (chunk_text 구조)

테이블: `classification_kcd_code_changes`  
스키마: `change_pair | old_code | old_text | new_code | new_text | change_type | insurance_focus_tags`

### 주요 change_type 종류 (20가지)
- `표제어 수정`, `표제어 수정(영문)`
- `코드 수정`, `코드 추가`, `코드 삭제`
- `제외 수정`, `제외 추가`, `제외 추가 및 수정`
- `내용 수정`, `내용 추가`, `내용 추가 및 수정`
- `포함 추가`, `주 수정`, `주 및 코드 추가`

### 샘플 (KCD-6차 신구대비표.xlsx)

```
change_pair: KCD-5_to_KCD-6
old_code: A02.1 / old_text: 살모넬라 패혈증(Salmonella septicaemia)
new_code: A02.1 / new_text: 살모넬라 패혈증(Salmonella sepsis)
change_type: 표제어 수정(영문)
```

```
change_pair: KCD-5_to_KCD-6
old_code: C83.2 / old_text: 소세포 및 대세포 혼합(미만성)
new_code: (삭제됨)
change_type: 코드 삭제
```

**특징:** `old_code == new_code`인 경우가 대다수 (표제어/제외 기술 변경). 코드번호 자체 변경은 전체 6,683건 중 97건(1.5%)에 불과.

## 5. 신구대조표 차수 간 연결 추적 가능성

**현재 구조:**
- `change_pair` 필드로 전환 단계 식별 가능 (KCD-5→6, 6→7, 7→8, 8→9)
- KCD-4→5 데이터 없음
- 체인 구성 가능: `old_code`(5차) → `new_code`(6차) → 6차를 old로 7차 조회 → ...

**실용성:**
- 코드번호 변경(97건)은 소수라 체인 구성의 실제 활용처가 제한적
- 대부분의 변경은 "같은 코드, 다른 표제어/제외 기술"
- 삭제된 코드(특히 혈액암 C83~C96)가 구 약관 계약일 기준 판단에 유용할 수 있음

## 6. KCD-9 원문 식별 및 조사보고서 활용 방식

### 6-1. KCD-9 원문 식별

```sql
-- KCD-9 원문만 조회
SELECT code, term_ko FROM classification_kcd_codes
WHERE kcd_version = 'KCD-9' AND code BETWEEN 'C00' AND 'C97Z'
ORDER BY code;
```
- 전체 78,189건 중 C00-C97: 1,086건, D00-D09: 111건, D37-D48: 182건

### 6-2. 조사보고서에서 이 데이터 사용 방식

코드베이스에서 `medical_issue_codes` 테이블은:
- `source_type: 'internal_medical_issue_code'`로 RAG 검색에 활용
- `ragSearch.ts`의 12개 source_area 중 `medical_issue_codes` 포함
- KCD 원문(`classification_kcd_codes`)은 `source_type: kcd_classification`으로 `rag_master_chunks`에 동기화됨
- 신구대조표(`classification_kcd_code_changes`)는 **rag_master_chunks에 미동기화** (현재 RAG 검색 외)

**현재 조사보고서 활용:** `classification_kcd_codes` → `rag_master_chunks` 동기화 → RAG 검색 경로  
**신구대조표 현황:** DB에 6,683건 존재하나 RAG 미연결

## 7. 재가공 방식 권고

### 7-1. 신구대조표 RAG화 (낮은 우선순위)

신구대조표를 `rag_master_chunks`에 동기화하면 "이 코드가 예전에 존재했는가", "차수 변경 시 어떻게 바뀌었는가"를 RAG 검색 가능해진다.

**적용 케이스:** 보험사가 "구 약관 기준으로는 이 코드는 암이 아니었다"고 주장하는 분쟁  
**구현 방법:** `syncReferenceDatasetsToRagMaster.js` 확장 또는 별도 스크립트

### 7-2. baseline 암 75% 개선 — 직접 경로 (높은 우선순위)

신구대조표는 baseline 암 케이스 75% 문제의 직접 원인이 아니다. 실제 약점은:

| 약점 | 개선 방향 |
|-----|---------|
| 암 FSS 분쟁 사례 부족 | FSS 분쟁 데이터 암 케이스 필터링 강화 |
| 경계성 종양 보험 해석 논거 부족 | D37-D48 관련 금감원 분쟁 사례 추가 |
| 보험 약관 암 정의 섹션 미매핑 | policy_terms_chunks 암 관련 조항 임베딩 |
| 제자리암(D05, D09) 보험금 지급 근거 약함 | 의학 가이드라인 + 판례 보강 |

### 7-3. 신구대조표 활용이 유용한 실제 케이스

혈액암 관련 분쟁: KCD-5에서 존재하던 C83.2, C84.2, C91.2 등이 KCD-6에서 삭제됨  
→ 구 약관 적용 시기(2010년 이전) 계약자 vs 보험사 분쟁에서 활용 가능

좌/우측 신규 코드 추가 (C56.0/1, C64.0/1 등):  
→ 계약일과 진단일 사이 차수 전환 시 코드 존재 여부 확인에 활용 가능
